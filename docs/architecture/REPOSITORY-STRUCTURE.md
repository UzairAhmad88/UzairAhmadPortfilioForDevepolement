# Repository Structure & File Placement Guide

## 1. Top-Level Directory Layout

```
.
├── .agents/                 <- Workspace agent skills & configuration
├── .astro/                  <- Generated Astro build cache and type declarations
├── .github/                 <- GitHub issue templates, workflows & CI configs
├── dist/                    <- Production static build output (generated by npm run build)
├── docs/                    <- Master engineering documentation suite
├── public/                  <- Raw static assets (favicons, images, manifest)
├── scripts/                 <- Node.js operational & sync scripts (sync-projects, etc.)
├── src/                     <- Application source code
│   ├── components/          <- Reusable Astro UI components
│   ├── data/                <- Canonical content data files (TypeScript source of truth)
│   ├── layouts/             <- Base HTML layouts & document shells
│   ├── lib/                 <- Business logic, engines, graph builders, and utilities
│   ├── pages/               <- Astro routing tree & dynamic slug pages
│   ├── styles/              <- Design tokens, global CSS, and utility classes
│   └── types/               <- TypeScript domain models and interface contracts
├── tests/                   <- Automated test suites
│   ├── integration/         <- End-to-end and integration tests
│   └── unit/                <- Fast unit test suites (node:test)
├── astro.config.mjs         <- Astro configuration (SSG, sitemap integration)
├── package.json             <- Package metadata, dependencies, and verified scripts
└── tsconfig.json            <- TypeScript strict compiler configuration
```

---

## 2. Directory Placement Rules

| Directory | What Belongs Here | What DOES NOT Belong Here |
|:---|:---|:---|
| `src/data/` | Typed static data files exporting canonical arrays (`projects.ts`, `lab.ts`, `research.ts`). | Dynamic runtime state, API clients, or UI templates. |
| `src/types/` | Pure TypeScript interfaces and type definitions (`project.ts`, `lab.ts`, `site.ts`). | Concrete data instances or executable logic. |
| `src/components/` | Modular Astro components with scoped styles (`LabItemCard.astro`, `Nav.astro`). | Page-level layout shells or raw database operations. |
| `src/pages/` | File-based routes generating HTML endpoints (`index.astro`, `work/[slug].astro`). | Deep business logic or shared non-page components. |
| `src/lib/` | Pure algorithmic engines (`graphBuilder.ts`, `discoveryEngine.ts`, `timelineEngine.ts`). | Presentation HTML or raw component markup. |
| `src/styles/` | Global CSS variables, reset, design tokens (`variables.css`, `utilities.css`). | Ad-hoc inline style tags. |
| `tests/unit/` | Fast, deterministic `node:test` suites asserting invariants. | Slow browser automation or flakey network dependencies. |
