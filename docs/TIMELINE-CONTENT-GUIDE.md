# Personal Engineering Timeline — Content Writing Guide

## 1. Editorial Voice & Principles

Timeline event summaries must remain:
1. **Factual & Grounded:** Accurately describe the engineering challenge, architecture, or model without promotional language.
2. **Concise:** Descriptions should be 1 to 3 sentences focusing on problem, approach, and key outcome.
3. **Free of Personal Evaluation:** Avoid subjective skill claims (e.g. "Mastered PyTorch", "Became an expert in quantitative engineering").

---

## 2. Event Writing Template

```
[Title]: [Clear Name of System / Experiment / Research Paper]
[Tagline / Domain]: [High-level technical domain or role]
[Description]: [1-2 sentences outlining the core problem and engineering approach]
[Takeaway / Insight]: [1 sentence technical finding or mathematical takeaway]
[Technologies]: [List of normalized technology IDs actually used]
```

### Approved vs. Unacceptable Copy

| ❌ Unacceptable Promotional Copy | ✅ Approved Editorial Timeline Copy |
|---|---|
| "This incredible AI bot transformed my trading portfolio and beat the market." | "Engineering an end-to-end quantitative research pipeline in Python and PyTorch with walk-forward risk evaluation and stationarized feature extraction." |
| "Learned React and became a full-stack master." | "Architecting modern React/Next.js client applications with strict TypeScript interfaces and server-rendered data fetching." |
| "Fixed stupid greenlet bug that wasted my whole day." | "Diagnosing greenlet concurrency exceptions when combining SQLAlchemy ORM relationships with asynchronous FastAPI route handlers." |
| "Built hospital app for fun." | "Architecting a multi-tenant hospital management system with role-based access control and transactional auditing." |
