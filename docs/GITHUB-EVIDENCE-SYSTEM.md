# GitHub Intelligence — Evidence System

## 1. What Constitutes Engineering Evidence?
External GitHub metadata serves as verifiable proof that an engineering artifact exists in the real world:
- **Repository Visibility**: Confirms public access for inspection.
- **Default Branch Tree**: Direct link to source code files (`/tree/main`).
- **Commit History**: Verifiable commit records substantiate development timeline.
- **License**: Legal licensing terms governing code reuse.
- **Detected Technologies**: Verified language and library usage extracted from dependencies and repo topic tags.

---

## 2. What is EXCLUDED from Evidence?
To maintain engineering truthfulness and avoid vanity metrics:
- **Star Leaderboards**: Repository stars are not treated as quality metrics.
- **Lines of Code (LOC)**: Code volume does not correlate with architecture quality.
- **Proficiency Percentages**: Language byte counts are never converted into self-assessed "Expert" claims.
- **Automated Summary Ingestion**: Unsanitized README text is never injected directly into project case study narratives.
